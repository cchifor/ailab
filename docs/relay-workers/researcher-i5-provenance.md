# Researcher installation: where each I5 value comes from

Step I5 of `docs/runbooks/relay-researcher-installation.md` commits the two files that
`scripts/relay-researcher-bundle.py import` wrote from the I4 bundle:
`kubernetes/apps/relay-researcher/pins/pins.yaml` and `kubernetes/apps/relay-researcher/agent/config.json`.
Neither is hand-edited. `config.json` is the importer's canonical compact JSON, byte for byte. Its
`leadership` block is the reviewed T1 overlay (`LEADERSHIP_OVERLAY` in `scripts/relay-researcher-bundle.py`),
which the importer applies over the prepared 15/10/2 after verifying the bundle. This
table ties every filled value to its source, so the policy can be audited without re-running the
tools.

Pinned inputs (`docs/relay-workers/researcher-binding-inputs.json`, `release`): Gitea release 2142
(v0.10.3, source `c0fe50f030eac65d78a113e42797c5fe8c395233`), with these asset sha256s:

Neither changes a leadership decision, timing or request; v0.10.8 also carries the 30/20/2 tests of relay #559. It replaced the v0.10.7 agent release (source `61c02f76`), which had replaced v0.10.6 (source `1599d06e`) and v0.10.5 (source `7521974a`). The agent's Lease annotation is unchanged since v0.10.6: `relay.chifor.me/lease-write` (a random UUID per write, used to prove a late-landing renewal). A hedged request is a second identical GET or PUT on a fresh connection, so its Lease requests are still only GET and PUT on `leases/relay-infrastructure-agent` and POST on the Lease collection (no list or watch), and `kubernetes/apps/relay-researcher/agent/rbac.yaml` already grants `get` and `update` on that resourceName and `create` on leases: no RBAC change is needed.
